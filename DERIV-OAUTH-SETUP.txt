TRADE SCHEME FX — DERIV OAUTH + DEMO EXECUTION SETUP

OAuth foundation
- /api/deriv/connect starts Deriv OAuth 2.0 Authorization Code + PKCE.
- /api/deriv/callback validates state, exchanges the code server-side, encrypts the access token with AES-256-GCM, and stores it using Supabase service role.
- Access tokens are never returned to browser code.
- Deriv does not issue OAuth refresh tokens. When expires_in passes or Deriv returns 401, the customer must reconnect.
- OAuth requests only the trade scope (least privilege for account listing, Demo OTP, and trading).

Required Deriv application setup
1. Register an OAuth application in the Deriv developer dashboard.
2. Allow the trade scope for the app.
3. Register the exact callback URI used by the deployment. Production default:
   https://www.tradesche.com/api/deriv/callback
4. If connecting from a Vercel Preview, register that Preview callback URI too and set DERIV_REDIRECT_URI and DERIV_SITE_URL for the Preview environment to that Preview host. Preview callback URLs must match exactly.
5. Add the Deriv OAuth Client ID to Vercel as DERIV_CLIENT_ID.

Required Vercel server environment variables
- DERIV_CLIENT_ID: Deriv OAuth App ID.
- DERIV_REDIRECT_URI: exact registered callback URL.
- DERIV_SITE_URL: base URL to return to after OAuth.
- DERIV_TOKEN_ENCRYPTION_KEY: random 32-byte key encoded as 64 hexadecimal characters.
- DERIV_OAUTH_ENABLED: keep false until the OAuth application and redirect URI are ready; set true only for the deployment being tested.
- DERIV_DEMO_TRADING_ENABLED: keep false until the Demo execution migration is applied and the Preview configuration is verified; set true for Preview only when ready.
- SUPABASE_SERVICE_ROLE_KEY: server-only Supabase secret. Never use a NEXT_PUBLIC_ prefix.
- NEXT_PUBLIC_SUPABASE_URL and NEXT_PUBLIC_SUPABASE_ANON_KEY: existing public Supabase configuration.

Generate the encryption key locally with:
  openssl rand -hex 32
Keep the output private and add it only as a Vercel Secret. Never send it in chat or commit it to GitHub. Do not rotate this key after customers have connected unless you first implement a secure re-encryption migration for all saved tokens.

Database setup
1. Apply supabase/deriv-connections.sql if the deriv_connections table does not exist yet.
2. Apply supabase/senfx-deriv-demo-execution.sql after the existing Deriv connections migration.
3. The new migration adds active Demo account selection fields, a customer-scoped Demo order audit table, and a $20 per-account daily Demo loss ledger.

Demo account workflow
1. Sign in to Trade Scheme FX.
2. Connect Deriv through OAuth.
3. Select an active Demo account in the dashboard. Real accounts are not selectable for SENFX Demo execution.
4. Open /demo-trading and connect to the Demo session.
5. Request a fresh Deriv proposal and review it.
6. Confirm one Demo purchase. The first release fixes the stake at 10 account-currency units, duration at 5 minutes, one active contract at a time, and the daily SENFX Demo gross-loss cap at 20 account-currency units.
7. SENFX reserves the full stake before the buy request. It verifies the created contract on Deriv and reconciles final P/L server-side before releasing the reservation.

Execution and safety boundaries
- The app issues Demo OTP URLs only. The OTP is short-lived, single-use, and limited to Deriv's /trading/v1/options/ws/demo endpoint.
- The Real WebSocket endpoint is not used by this feature. No Real-account buy or sell endpoint is provided.
- The $20 cap tracks SENFX-originated Demo contracts in the selected account. It does not include trades placed directly on Deriv outside SENFX.
- If a buy response is ambiguous, SENFX keeps the full stake reserved. Do not repeat the purchase until the order is reconciled.
- Demo contract execution is different from the illustrative public-tick paper simulator. Their history and P/L must remain separately labelled.
- This is a manual Demo contract test first. Automatic bot execution is a later phase after the Demo lifecycle is proven on test accounts.
- No profit is guaranteed. Do not treat Demo outcomes as evidence of future live profitability.

Support
Never share OAuth access tokens, OTP URLs, encryption keys, or Supabase service-role secrets in chat, screenshots, logs, or GitHub.
