# Autonomous Intelligence Core 5.0
Upload additive files to a development branch. Run `node tests/quantum-ai5.mjs`.
After database backup and review, apply `supabase/quantum-drafts/ai-core5.sql` once. Configure an existing approved Railway worker with Node 22+, start command `node worker/quantum-ai/run.mjs`, server-only SUPABASE_URL and SUPABASE_SERVICE_ROLE_KEY, optional QUANTUM_SYMBOLS (default R_100). Never put secrets in GitHub or NEXT_PUBLIC variables. Do not start multiple workers for the same symbol. Verify costs before enabling continuous operation. Check logs and query quantum_ai_latest for fresh timestamps and quantum_ai_batches for 300-tick batches. The shared read helper must be wired into existing bot controllers separately; the 16 entries are research recipients, not live trading bots. The adaptive model uses smoothed digit frequencies and first-order transitions, scored before updating with the next outcome. No broker orders. No claim of predictive advantage. Model state resets on restart; persisted raw batches can support future offline training but are not automatically restored. Partial batches and queued data may be lost on abrupt shutdown. Storage grows without retention; set a reviewed retention policy before long-running deployment. Feed gaps are possible; same-second ticks are rejected. Live connectivity and database permissions not tested here. No existing files replaced.
